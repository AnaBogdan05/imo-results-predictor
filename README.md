# Predicting IMO Performance from Prior International Olympiad Results

Can a contestant's result at the International Mathematical Olympiad be predicted from
their earlier international olympiads (JBMO, BMO, EGMO, RMM, APMO, MEMO, PAMO) and from
their country's recent IMO history, using only information available before that IMO?

Project for *IAPD*, MSc Data Science, UNSTPB — Ana-Maria-Iulia Bogdan.

## Reproducing

```bash
pip install -r requirements.txt
cd extraction
python crawl_moresults.py          # 4 requests
python crawl_imo_official.py       # 27 requests, ~2 min
python crawl_jbmo_hms.py           # ~40 requests, ~2 min
python parse_jbmo_results.py       # needs the PDFs listed in data/sources/README.md
python build_raw_tables.py
python check_jbmo_code_order.py
python build_features.py
python validate_dataset.py
cd ../analysis
python descriptives.py
python baselines.py
```

Downloads are cached in `data/cache/`; re-running never requests a page twice.

## Data collection

| Source | What | How |
|---|---|---|
| imo-official.org | IMO individual results 2000–2026: per-problem scores, total, rank, award, official contestant id | one page per year, `/results/individual/year/<year>/`; rows are parsed from the JSON embedded in the page |
| moresults.org | results of IMO, EGMO, MEMO, RMM, APMO, BMO, JBMO, PAMO, EMO with person profiles linking participations | the site renders every page in the browser from one data file, `/data/olympiad_data.json.gz`, which the crawler locates through the site's JavaScript bundle and downloads once |

**JBMO editions missing on moresults.org** (2018, 2019, 2020, 2022) come from the organisers;
sources in `data/sources/README.md`:

| Edition | Source | Coverage |
|---|---|---|
| 2018 | hms.gr medal tables (HTML) | medallists, with problem scores |
| 2019 | cms.org.cy PDFs | medallists, names and medals only |
| 2020 | hms.gr PDF (online JBMO, 9–13 September, before IMO 2020) | **every contestant**, with problem scores |
| 2022 | jbmo2022.pmf.unsa.ba PDF | medallists and honourable mentions, with problem scores |

The 2018 and 2020 results identify contestants by codes (`ROMANIA2`, `ROM2`); the number is
the contestant's position on the team page of hms.gr, which `crawl_jbmo_hms.py` collects.
`check_jbmo_code_order.py` tests this mapping: a contestant's JBMO score predicts their later
IMO percentile better with the real mapping than with names shuffled within each team
(Spearman 0.51 vs 0.34 on average for 2020, p = 0.03; 0.59 vs 0.46 for 2018, p = 0.09).
Partly published editions have no percentile and are marked in `competitions.csv` (`coverage`).

**Permissions and terms of use** (robots.txt checked 2026-10-20, terms 2026-11-11):

| Site | robots.txt | Terms of use |
|---|---|---|
| imo-official.org | no `Disallow` rules; content-signal preamble but no signal set, so it neither grants nor restricts any use | no terms-of-use page; footer "© International Mathematical Olympiad". The contact page states that data are held in compliance with EU data-protection law and that participants may ask to be made anonymous; such participants appear without a name on the site and stay anonymous here |
| moresults.org | `Allow: /` for all agents, with a sitemap | no terms-of-use page; the site's code and data repositories on GitHub (`matholympiadresults/moresults-web`, `moresults-data`) have no licence. The site says its data are mirrored from the official olympiad websites and gives a contact address for corrections and redactions |
| JBMO organisers | see `data/sources/README.md` | no terms found |

No site grants an explicit licence, and none restricts this use. The data are used for
non-commercial academic research, the sources are cited, nothing is redistributed in its
original form, and names are removed from every published table.

**Linkage.** IMO rows are joined across sources by the official contestant id
(`people.source_ids.imo` on moresults.org). Of 15,056 official rows, 15,049 link by id, 2 by
year + country + total, and 5 (anonymous or unmatched) stay without cross-competition
history; totals and awards agree on every id-linked row. All 3,702 contestants who took part
in several IMOs map to a single moresults person. See `data/raw/linkage_report.txt`.

**Repairing split profiles.** moresults.org sometimes creates two profiles for one person
when the name is written differently between competitions ("Gualdi Pietro" / "Pietro Gualdi",
"Avădănei" / "Avadanei"). Profiles are merged when they have the same name up to word order,
accents and punctuation, the same country, never appear in the same competition edition, and
all their events fit in 7 years. This merges 600 profiles in 585 groups and reassigns 1,104
participations. A random sample of 14 merges was checked by hand and all were the same person.

**Splitting over-merged profiles.** The opposite also happens: 8 moresults profiles join
different people with the same name, e.g. one Takuya Inoue at IMO 2007 and another at IMO
2014–2016, or an APMO 2024 entry attached to an IMO 2016–2019 contestant. Profiles covering
more than 7 years are split wherever more than 3 years separate consecutive events.

**Privacy.** Names are used only inside `data/cache/` and never written to `data/raw/` or
`data/final/`. Contestants are identified by a salted hash of the moresults person id; the
salt stays in the cache. Note that results are public, so a row can still be traced back
through its year, country and scores: the ids are pseudonyms, not anonymisation.

## Dataset

Every column of every table is described in **[`docs/data_dictionary.md`](docs/data_dictionary.md)**;
`validate_dataset.py` fails if a column is missing from it.

### Raw tables (`data/raw/`): relational, close to the sources

| Table | One row per | Rows |
|---|---|---|
| `participations.csv` | contestant × competition edition (IMO 1959–2026 + 8 other olympiads) | 36,564 |
| `competitions.csv` | competition edition, incl. `coverage`: full, or medallists only | 178 |
| `contestants.csv` | contestant: career summary, `gender_proxy` | 21,105 |
| `countries.csv` | country: name, continent, competitions attended | 157 |

### Final tables (`data/final/`): one row per contestant per IMO, 2008–2026

| Table | Columns | Use |
|---|---|---|
| `imo_contestants_full.csv` | 114: 3 id + 12 target + 2 meta + 97 features | models (Phase 2), feature importance |
| `imo_contestants.csv` | 29: a selection of the above | baselines, presentations, a quick look |

11,169 rows, 7,147 contestants, 133 countries. Columns are grouped by prefix:

| Prefix | Group | Examples |
|---|---|---|
| `id_` | identifiers | `id_contestant`, `id_year`, `id_country` |
| `target_` | what is predicted | `target_total` (0–42), `target_award`, `target_rank_pct`, `target_z` (standardised by year and problem), `target_p1`…`target_p6` |
| `meta_` | error analysis only, not features | `meta_gender_proxy`, `meta_continent` |
| `imo_` | earlier IMOs | `imo_attempt`, `imo_best_pct`, `imo_last_award`, `imo_years_ago` |
| `hist_` | all earlier events | `hist_n_events`, `hist_best_award`, `hist_mean_rank_pct`, `hist_trend` |
| `jbmo_` … `pamo_` | one block per olympiad, same columns | `_status`, `_missing_editions`, `_n`, `_best_pct`, `_best_rank_pct`, `_best_award`, `_years_ago` |
| `team_` | the IMO team that year | `team_size`, `team_rank_by_history` |
| `country_` | the country's earlier results | `country_imo_mean_pct_3y`, `country_medal_rate_3y`, `country_n_regional_3y`, `country_access_<c>` |
| `context_` | the IMO edition | `context_is_host`, `context_online` |

**Leakage control.** A feature uses an event only if it happened in an earlier year, or in
the same year at a competition always held before the IMO (RMM, APMO, EGMO, BMO, JBMO).
MEMO (after the IMO), PAMO and EMO (dates vary or unverified) count only from earlier years.
`meta_gender_proxy` uses the whole career and is therefore not a feature.

**Missing values are explicit.** Counts are 0 and scores NaN when a contestant has no such
event. `<c>_status` says why a competition is absent: `not_participated` (all editions in the
6 years before the IMO are fully published), `no_data` (one of them is missing or partial, so
absence is uncertain), or `not_held` (the competition did not exist yet).

**Validation.** `validate_dataset.py` recomputes key quantities independently (21 checks): no
duplicates, totals within range, problem scores adding up (3 rows differ in the source data),
one final row per IMO participation, no future events in any feature, NaN for missing history,
status columns consistent with counts and coverage, `target_z` centred per year, country features
and targets equal to a direct recomputation, every column documented. All checks pass.

**Coverage gaps.** Some editions are still missing: JBMO 2011, 2017;
BMO 2006, 2007, 2012, 2013; RMM 2014, 2022; PAMO 2008–2011, 2014, 2015, 2020. They show up as
`<c>_status = no_data` and in `<c>_missing_editions`. APMO publishes only the top 10
contestants of each country, so APMO percentiles are relative to those.

**Neutral team.** At IMO 2022–2025 the Russian team competed without a flag and neither site
lists a country; these 24 rows are assigned `RUS` so that country history is continuous.

## Phase 1 results

Train IMO 2008–2022 (8,646 rows), test IMO 2023–2026 (2,523 rows); 95% bootstrap intervals.
Linear and logistic regression are fitted on the 20 features of the compact table.

| Score (0–42) | MAE | RMSE | R² |
|---|---|---|---|
| Training mean | 8.37 | 10.20 | −0.04 |
| Country history (3 IMOs) | 4.97 [4.81, 5.11] | 6.31 | 0.60 |
| Linear regression | 4.36 [4.23, 4.49] | 5.52 | 0.70 |

| Award (5 classes) | Accuracy | Within one award | Balanced accuracy | Macro-F1 |
|---|---|---|---|---|
| Majority class | 0.25 | 0.74 | 0.20 | 0.08 |
| Country modal award | 0.47 | 0.91 | 0.45 [0.43, 0.47] | 0.46 |
| Logistic regression | 0.52 | 0.91 | 0.54 [0.52, 0.56] | 0.51 |

On all 108 features of the full table the linear models do slightly worse (R² 0.67), as expected
with many correlated columns; that table is meant for the tree models of Phase 2.
Full tables, confusion matrix and coefficients: `analysis/results/baselines.md`;
descriptive statistics: `analysis/results/descriptives.md`.
